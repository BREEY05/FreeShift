## 一、项目概述

### 1.1 项目背景

多人共同排课时，最大的痛点是“凑时间”：每个人手里有自己的课表/空闲时间，靠群里发截图、口头对表，效率低且容易漏。FreeShift 把每个人的空闲时间汇总到一张表上，自动算出“所有人都空闲”的公共时段，并能按权重推荐最合适的上课/开会时间。

### 1.2 项目目标

| 目标 | 说明 | 验收标准 |
|---|---|---|
| 高效录入 | 成员按周录入自己的空闲格 | 录入一格 ≤ 2 次点击 |
| 一图看清 | 全员空闲度热力表 | 一屏内看到整周 5×10 格空闲分布 |
| 智能推荐 | 自动给出公共空闲时段 | 给出连续块 + 5 因子评分 + 备选方案 |
| 公平性 | 避免总让同几个人迁就 | 输出基尼系数与个人空闲占比 |
| 可迁移 | 数据能带走 | CSV 导出/导入全量往返一致 |

### 1.3 交付物

1. Web 应用（前端 + 后端 API + SQLite 数据库），部署在 https://freeshift.ainavi.online
2. 本地离线版（Windows 双击即用，无需联网）
3. 源文件与部署文档（GitHub 仓库）
4. 项目演示与答辩材料

| 天 | 主题 | 里程碑 | 结束状态 |

### 4.2 详细里程碑

#### 里程碑 1：地基可用（D1 18:00）

**验收标准**
- [ ] 仓库初始化完成，`pnpm install && pnpm dev` 一条命令能起来

- [ ] 统一响应格式与错误处理就位

**风险**：技术选型反复 → A 在 D1 上午必须定死，后续不再改

#### 里程碑 2：数据可录入（D2 18:00）

**验收标准**
- [ ] 成员：增删改查、启用停用、排序，页面可用

**风险**：交互细节反复 → C 先做低保真原型给全组过一遍，再写代码

#### 里程碑 3：结果可看（D3 18:00）

**验收标准**
- [ ] 热力表：整周 5×10 格，按空闲人数分 5 档着色，图例正确
- [ ] 筛选：按成员筛选后热力值重算
- [ ] 周次切换：单周/双周/全部周视图正常
- [ ] 公共空闲块：连续空闲段合并（跨小节 ≤20 分钟视为连续）
- [ ] 推荐：给出 Top N 时段，带 5 因子评分条
- [ ] 备选方案：主方案冲突时给出替代时段

**风险**：算法边界情况多 → B 先写测试用例再写实现，用测试驱动

## 六、协作机制

### 6.1 每日站会（每天 9:30，15 分钟）

每人回答三个问题：
1. 昨天完成了什么
2. 今天要做什么
3. 有什么卡住的地方

卡住超过 1 小时的问题，立即升级给组长。

### 6.2 代码协作规则

- **分支**：`main` 保护，功能走 `feat/<模块>-<简述>`，如 `feat/board-heatmap`
- **合并**：组长 review 后合并，合并前必须本地跑通
- **冲突预防**：按模块切分文件，避免多人改同一文件
- **提交信息**：`feat: xxx` / `fix: xxx` / `docs: xxx`

### 6.3 接口契约先行

D1 结束前必须产出接口文档（URL、入参、出参、错误码），前后端各按文档开发，不互相等。这是 4 天能做完的关键。

### 6.4 每天必做的三件事

1. **部署**：每天下班前把当前版本部署到线上（不攒到最后）
2. **回归**：跑一遍全量测试
3. **日报**：组长汇总进度，标记风险

## 七、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 需求膨胀，功能越加越多 | 做不完 | D1 定死范围，新增需求进“下版本清单” |
| 前后端接口对不上 | 返工 | 接口契约先行，D1 冻结 |
| 算法边界情况多 | D3 卡住 | 先写测试用例，测试驱动开发 |
| 最后一天部署出问题 | 无法交付 | 每天部署一次，问题早暴露 |
| 某成员进度落后 | 拖累整体 | 每日站会暴露，组长当天调配人手 |

### 降级预案（如果 D3 结束仍未完成核心功能）

按优先级砍功能：
1. **必须保住**：成员、模板、空闲录入、热力表（这是项目的根本价值）
2. **可以简化**：推荐算法的因子数量（5 个减到 3 个）
3. **可以砍掉**：统计分析、备选方案、本地离线版

## 十、附：技术架构速览

```
浏览器
   │ HTTPS
   ▼
Nginx (443)  ── 静态文件 ──> 前端构建产物
   │ /api
   ▼
Node 24 + Fastify (127.0.0.1:3100)
   │
   ▼
SQLite (/data/freeshift/freeshift.db)
```

- **前端**：React 18 + Vite + Tailwind CSS + TanStack Query
- **后端**：Node 24（原生 TypeScript）+ Fastify 5 + Zod 校验
- **数据**：SQLite（WAL 模式），无独立数据库进程
- **部署**：systemd + Nginx，2 核 2G 小机器，常驻内存约 54MB

选型理由：2 核 2G 的机器资源有限，SQLite 省掉一个数据库进程，内存占用小；Node 24 原生跑 TypeScript，不需要额外编译步骤，部署简单。
